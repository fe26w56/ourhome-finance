# カレンダーUI改善および表示ロジック変更 要件定義書

## 1. 概要
カレンダー画面の視認性を向上させるため、縦方向の表示領域を約20%縮小し、よりコンパクトな表示とする。また、カレンダー生成ロジックを見直し、表示月の日付を含まない不要な翌月の週を表示しないようにする。

## 2. 現状の課題
1. **表示サイズ**: カレンダーの日付セルや行間の余白が大きく、画面の縦領域を占有しすぎている。
2. **不要な行**: 常に6週間分（42セル）を表示するロジックとなっており、月によっては最終週以降に完全に翌月の日付しかない行が表示されている（例：月末が土曜日の場合の翌週など）。

## 3. 機能要件

### 3.1 UIコンパクト化 (Option C)
*   **行間短縮**: カレンダーのグリッド行間 (`gap-y`) を現在の `4` (16px) から `2` (8px) 程度に縮小する。
*   **セルサイズ縮小**: 日付表示円のサイズ (`h-10 w-10`) を `h-9 w-9` (36px) 程度に縮小する。
*   **パディング調整**: 必要に応じてコンテナのパディングを微調整する。
*   **目標**: 全体として縦方向の高さを約20%削減する。

### 3.2 カレンダー生成ロジックの最適化
*   **動的な週数**: 固定で6週間分（42日）を生成するのではなく、表示月の最終日が含まれる週の末日（土曜日）までで生成を終了する。
*   **条件**: 表示されている最後の週に、当月の日付が1日も含まれていない場合（＝その行がすべて翌月の日付の場合）、その行は表示しない。
    *   *補足実装詳細*: 月の最初の日（ついたち）から開始し、月の最終日まで埋める。その後、最終日が属する週の土曜日まで翌月の日付で埋める。これで自動的に「当月を含まない翌月の週」は生成されなくなる。

## 4. 非機能要件
*   **操作性**: タップターゲットが小さくなりすぎないよう配慮する（36pxはタップ可能な範囲内）。
*   **視認性**: フォントサイズや強調表示（今日、選択日）のバランスを維持する。

## 5. 成功基準
1. カレンダーの縦幅が目に見えて縮小していること。
2. 月末が週末にかかる場合などに、不要な翌月の行が表示されていないこと（例：2025年2月は2/1が土曜、2/28が金曜。4行または5行で収まるはず）。
